# 去除 MAVSDK 方案

状态：实施中；直接UDP与基础遥测已替换运行入口并移除MAVSDK，整体迁移尚未验收。此文取代此前MAVSDK选型；历史M1/M2实现与验收证据保留，仅证明旧实现。当前迁移分支源码已切换直接UDP；原UI工作区仍使用旧链路，不宣称整体迁移完成，不自动推进M3。

## 目标与分层

标准MAVLink XML（固定版本）→ mavgen生成Java消息/编解码代码 → Kotlin UDP链路/帧处理 → 连接会话与遥测适配 → 既有Readout/ViewModel/UI。不在运行时动态解释XML，不手写每个消息的字节布局。

优先核对PX4 v1.17.0实际使用的标准dialect及包含链，固定XML仓库提交、生成器版本、命令、生成产物与许可证；不能只按当前最新common.xml假设与固定飞控一致。生成工具只用于开发/构建，APP离线运行不依赖Python、XML下载或mavsdk_server。

## 本轮迁移边界

替换已有M1/M2连接与只读遥测能力，保留自动UDP预设、前台服务、断链重连、旧会话隔离、字段单位/有效性、地图、日志与回放。独立读写协程、有界队列、单调时钟、心跳目标识别；只有合法飞控心跳确认后进入connected，不因收到任意UDP数据判定连接。固定目标不被未知来源覆盖。

必须逐字段重建消息到领域读数的映射，核对坐标、缩放、无效哨兵、位掩码、电池单位、模式/解锁与状态文本；不沿用MAVSDK API单位直接解释线上值。MAVLink帧需覆盖v1/v2、CRC_EXTRA、扩展字段、截断补零、混合/残缺/错误帧及签名包处理；不能静默把未验证签名当作可信认证。

本阶段只实现维持现有遥测所需的心跳、发现和必要消息频率请求；具体GCS身份、飞控目标过滤、超时与频率按现有证据/固定PX4核对后落表。命令事务至少对频率请求区分发送、ACK、超时及不支持，不盲目循环重试。不增加解锁、起飞、任务上传、恢复、喷洒或其他未确认飞行动作。后续任务/命令微服务由本项目负责，不再依赖SDK内部握手，须在对应阶段单独明确协议契约。

## 模块与拆分

1. 固化XML/生成器与生成命令，验证Java产物在Android9可用、消息往返及固定测试帧。
2. 增加帧处理、UDP生命周期、目标识别/会话管理；接入既有ConnectionService和连接预设。
3. 逐项替换遥测适配，保持Readout等上层契约；回归健康、轨迹断段与原始采样时间。
4. 移除MavsdkConnection、LocalMavsdkEngine、MavsdkProcessService及相关Messenger/内部桥接中仅服务SDK的部分；更新GroundControlApp、Manifest、构建依赖与探针。未验证新链路前不把旧探针改名当作通过。
5. 删除MAVSDK Java/server/gRPC等实际不再使用的依赖。固定NDK的共享C++运行库/NOTICE注入须核对MapLibre等剩余原生依赖后再决定，不能因去掉MAVSDK就误删其他库需要的运行库。原生16KiB兼容仍需验证。

## 验收与风险

- 构建、单测、Lint；Java生成可复现，APK中无MAVSDK server及对应组件/无用依赖。
- 消息正常往返、CRC错误/未知消息、边界值/无效值、v1/v2及签名包处理符合明确策略。
- 无飞控/端口占用/错误目标/恶意或损坏UDP数据、预设快速切换、停止重启、旧会话及乱序回调隔离。
- 固定PX4 v1.17.0 SITL：自动连接、字段逐值对照、断链/重连、飞控重启、受控丢包/延迟/重复/乱序、过期/恢复；不能用假数据代替链路验收。
- 回归存储、日志、健康、地图与回放；UI由用户验证，不默认启动APP。Android9/目标遥控器及长稳缺条件时如实记录，旧MAVSDK探针通过不能替代新实现验证。

风险主要是SDK先前隐含承担的发现、流频率、数据组合、单位转换、生命周期和事务重试将由本项目接管。实现前需核对并记录dialect/工具固定版本、心跳超时/GCS身份/目标筛选、签名处理与消息频率；涉及新增飞行语义或范围变化先向用户确认。
