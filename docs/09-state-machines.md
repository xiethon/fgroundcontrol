# 状态机设计清单

候选模型；T03 确认转换表后再实现。

| 状态对象 | 候选状态 | 转换依据 |
| --- | --- | --- |
| 连接 | 未连接、连接中、在线、失联、重连中 | 传输状态、心跳与超时 |
| 上传 | 未上传、校验中、上传中、成功、失败 | 协议握手、ACK 和超时 |
| 命令事务 | 待发送、等待 ACK、等待状态、成功、拒绝、超时、结果未知 | 命令响应与飞控实际状态 |
| 执行 | 待执行、执行中、暂停、返航、完成、中断、失败、待核对 | 飞控状态与执行记录 |

每条转换记录：当前状态、事件、前置条件、目标状态、副作用、持久化点及失败结果。

必须确认：

- 开始的任务匹配条件，暂停/继续的位置与模式，停止后的飞机行为。
- 返航后的任务归属与结束条件，完成/中断/失败的区别。
- 断线时本地状态、超时后如何查询，重复命令如何处理。
- 重启后如何识别飞控任务、匹配上传快照和恢复进度。

共同约束：发送成功不等于动作完成；ACK 接受不代替实际状态；旧会话消息无效；结果未知时先核对，不盲目重试；不自动续飞。

## 2026-11-16 补充确认

- 无线链路使用 UDP；监听/目标端口、单播/广播、地址配置与发现方式待明确。
- 正常结束动作可选悬停或返航，随本次任务上传固定；进入末尾动作即结束作业计时。以飞控实际任务进度/状态确认进入，不能以命令发送或 ACK 替代。
- 作业计时结束与飞机返航/落地状态分开记录；首期不控制喷洒，末尾不附加喷洒关闭命令。
- 恢复核对失败交由人工处理，不自动续飞、不自动重传或修改飞控任务；失败只需简单弹窗，关闭不触发命令。

| 暂停 | 请求 holdPosition；Manager 立即停表并记断点 | 请求后等待飞控实际 Hold 状态再确认暂停；原乐观状态更新不继承 |

恢复核对失败：简单弹窗说明原因，关闭仅关闭提示，不发送飞行命令。

## 已确认转换（取代上表对应待确认项）

| 当前状态/事件 | 前置条件 | 结果及持久化 | 失败结果 |
| --- | --- | --- | --- |
| 执行中请求暂停 | 当前 UAV/任务匹配，遥测有效 | 等待实际 Hold，再记暂停、停表及断点 | 拒绝不记成功；超时/断线待核对 |
| 暂停请求继续 | 已解锁，任务匹配，遥测有效 | 等待实际 Mission，再记执行中并恢复计时 | 未解锁明确拒绝，不自动解锁；其余失败待核对 |
| 执行中/暂停请求停止 | 当前 UAV/任务匹配，遥测有效 | 等待实际 Hold，再记中断、停止计时并保留恢复记录 | 不因请求或 ACK 标记完成；超时/断线待核对 |

已处于 Hold 的停止也须核对新鲜实际状态；重复反馈不得重复写入结束结果。具体超时、命令映射与位置语义仍需 T02/T03 完整固化。

## 最新确认补充

- 待执行请求开始：要求已解锁，未解锁拒绝且不发解锁命令；其余开始前置条件仍需形成完整表。
- 手动返航：结束作业计时，记中断并保留恢复记录，继续跟踪返航/落地。拒绝、超时、断线不得假定已返航；请求期间计时与最终状态证据细节待固化。
- MAVSDK 调用成功不替代飞控实际状态达成，旧会话回调不能完成当前事务。
