# AI 阶段推进提示词

每阶段依次输入以下四段，收尾后再开始下一阶段。

统一参考：[设计与功能参考索引](20-reference-guide.md)。界面视觉查Figma节点，功能流程查参考项目；样式使用[共享token](19-ui-tokens.md)，参考不能代替需求确认。

## 1. 了解现状、对齐需求

```text
阅读 AGENTS.md、当前进度和推进计划，确定当前阶段，再按需检查需求、规则与代码。

涉及界面或功能移植时，按 docs/20-reference-guide.md 核对Figma目标节点与参考源码版本/文件；打开Figma使用内置浏览器。先区分视觉依据、功能依据与已确认需求，缺少关键结论不猜测。

只对齐当前阶段，暂不修改源码。简述：
- 阶段目标、现状与差距。
- 范围、不做事项、验收标准。
- 实现方案、涉及模块、风险与待确认问题。

集中提出必要问题，与我确认后，将结论记录到相关需求和当前进度。未确认的飞行行为不猜测，不展开下一阶段。
```

## 2. 开始实施和验证

```text
按本阶段已确认的需求与方案开始实施。先核对当前进度和确认记录，缺少关键结论时先询问。

实施前检查分支和工作区，保留已有改动；从 main 新建本阶段开发分支 `feat/<阶段>-<主题>`，确认已切换后再修改。若工作区改动妨碍切换，先说明并处理，不丢弃或夹带无关改动。

完成当前阶段范围，可拆小步骤持续推进；不提前实现下一阶段，不用占位实现冒充完成。

视觉按Figma目标节点实现，颜色/字体/布局复用统一token；功能参考 /Users/xiethon/fairland/fgroundcontrol 的对应调用及异常路径，记录参考版本和采用差异。设计示例不当作真实状态，参考飞行行为未确认不移植。

自查后运行相关 Android 构建，验证正常、边界和失败场景；纯文档检查内容与引用。UI 由我验证，只提供简短步骤和预期，不启动 UI、不截图、不做界面自动化。

更新任务状态和当前进度，简述完成内容、验证结果和待我验证项。缺少条件如实记录，不标记通过。本环节不提交或合并代码。
```

## 3. Review 收尾

```text
按 rules/review.md 审查当前阶段的全部改动，核对已确认需求、验收标准及验证证据，不只检查最后一次修改。

按 docs/20-reference-guide.md 核对设计节点、参考源码版本、采用差异及token使用；不把参考存在或构建成功当作需求/视觉验收通过。

检查飞行状态、异常路径、线程与生命周期、数据一致性和回归风险。修复发现的问题，运行必要的构建和回归验证；范围或飞行语义需改变时先确认。

更新任务状态与当前进度，简述修复结果、剩余问题、待用户验收项，以及是否具备源码收尾条件。未验证不得视为通过，不进入下一阶段，不提交或合并代码。
```

## 4. 源码管理

```text
按 rules/git.md 完成当前阶段源码收尾。

先核对分支、工作区、阶段改动、Review 和验收记录。若存在阻塞问题或未完成验收，先报告并停止收尾。

此输入授权提交本阶段相关改动，并在验收通过后合入本地 main；只暂存相关文件，保留无关改动，合并后检查结果。无可提交改动时不创建空提交。

分支使命结束后，确认改动已保留、无待保留提交和关联 worktree，再删除本地及同名远程分支并清理跟踪引用；main 保留。远程不存在时跳过。

不推送代码、不执行远程合并、不打标签、不发布；这些操作另等指令。权限或网络受限时记录未完成项，不强制删除。

更新当前进度，报告提交号、合并和分支清理结果。等待我发起下一阶段，不自动继续。
```
