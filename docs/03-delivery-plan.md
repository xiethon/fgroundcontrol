# 推进计划

| 阶段 | 工作与交付 | 退出条件 |
| --- | --- | --- |
| M0 需求冻结 | 明确硬件、链路、飞控版本、三种规划规则、执行语义、报告口径；定义协议与交互行为 | 阻塞事项确认，状态图与验收矩阵可评审 |
| M1 架构骨架 | 工程构建、分层、本地存储、三类日志接口、模拟数据与回放入口、平台连接原型 | 实机启动、离线存储、日志导出可用，硬件链路验证通过 |
| M2 只读闭环 | 连接、遥测、地图、健康告警、断线重连 | 数据符合协议约定，旧会话隔离，目标设备稳定运行 |
| M3 大田规划 | 任务框架，三种规划方式，保存编辑与航线校验 | 典型与异常几何样例通过，任务版本和规划结果可追溯 |
| M4 上传执行 | 上传事务、五类执行操作、实际状态同步 | SITL/台架验证 ACK、超时、拒绝、重复操作与断线场景 |
| M5 恢复报告 | 未完成任务、恢复核对、报告统计、日志关联 | 重启/重连恢复路径与报告数据通过核对 |
| M6 发布验收 | 实机综合验证、受控实飞、长时间运行、交付文档 | 验收矩阵完成，无未处理的飞行安全阻塞项 |

各阶段先评审后实施。M4/M5 安全验证完成前不得生产作业。

协议与资源准备见 08、10；任务见 06。

阶段闭环：目标确认 → 实现 → 验证 → Review 与修复 → 源码管理 → 用户确认进入下一阶段。未完成验收不跨阶段。
